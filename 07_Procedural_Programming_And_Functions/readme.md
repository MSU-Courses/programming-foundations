## Когда программа разрастается

### Одна и та же логика в нескольких местах

Представим бой героя с гоблином. Герой атакует первым, затем гоблин отвечает. Урон равен разнице между атакой и защитой, но не может быть отрицательным.

Запишем бой в псевдокоде:

```text
SET heroHealth = 100
SET heroAttack = 30
SET heroDefense = 12

SET goblinHealth = 60
SET goblinAttack = 15
SET goblinDefense = 10

SET damage = heroAttack - goblinDefense
IF damage < 0
    SET damage = 0
END IF
SET goblinHealth = goblinHealth - damage

SET damage = goblinAttack - heroDefense
IF damage < 0
    SET damage = 0
END IF
SET heroHealth = heroHealth - damage

OUTPUT goblinHealth
OUTPUT heroHealth
```

Гоблин потеряет 20 единиц здоровья, герой - 3. Однако расчёт урона здесь записан дважды. Если в игре появятся орки, ловушки и заклинания, одинаковую формулу придётся копировать снова и снова.

Теперь геймдизайнер меняет правило: _каждый удар наносит минимум 1 единицу урона_. Если формула встречается в десяти местах, менять придётся все десять. Одна забытая копия создаст ошибку, которая проявится не в каждом бою.

Повторение логики приводит к двум проблемам:

- _Сложнее изменять код_ - одно правило приходится исправлять во многих местах.
- _Легче допустить ошибку_ - некоторые копии остаются со старым правилом.

**DRY (Don't Repeat Yourself)** - принцип "не повторяйся": одно правило должно иметь одно основное место реализации[^1]. Для расчёта урона таким местом станет функция.

### Программа без имён для действий

Есть и другая проблема. В программе арены из шестой главы действия не названы: нужно самостоятельно прочитать циклы, чтобы понять, где проверяется ввод, где считаются удары и где перебираются волны.

Удобнее видеть план программы:

1. Прочитать урон.
2. Провести волны боя.
3. Показать итог.

Чтобы такой план стал кодом, нужно выделить действия в отдельные части и дать им понятные имена.

## Декомпозиция

**Декомпозиция (decomposition)** - разделение большой задачи на небольшие подзадачи, которые можно решать по отдельности.

Этот подход связан с **пошаговым уточнением (stepwise refinement)**: сначала описывают общий план, затем постепенно раскрывают детали каждого шага[^2].

Для арены верхний уровень выглядит так:

1. Прочитать урон игрока.
2. Провести три волны.
3. Вывести общее число ударов.

Каждую волну можно уточнить:

- подсчитать удары до победы над врагом
- прибавить их к общему результату
- сообщить о завершении волны

![Рисунок 7.1. Дерево декомпозиции арены: общая задача разбита на чтение урона, прохождение трёх волн и вывод итога](../_images/07/fig-decomposition.svg)

_Рисунок 7.1. Декомпозиция задачи "Арена"_

_Главная идея_: вместо одной большой программы мы получаем набор понятных действий. В командной разработке над движением, расчётом урона и сохранениями игры могут работать разные программисты.

## Процедурное программирование

**Процедурное программирование (procedural programming)** - подход, при котором программа состоит из именованных частей, вызывающих друг друга[^3].

**Подпрограмма (subroutine)** - такая именованная часть кода, которую можно выполнить по вызову. В C++ подпрограммы оформляются как функции.

Структурное программирование никуда не исчезает. Внутри каждой функции остаются знакомые конструкции: последовательность действий, условия и циклы. Функции лишь помогают собрать эти действия в понятную программу.

## Что такое функция

### Функция как чёрный ящик

**Функция (function)** - именованная часть программы, которую можно вызвать для выполнения определённой задачи.

Представьте функцию расчёта урона как чёрный ящик:

- вход - атака `30` и защита `10`
- действие - вычисление разницы
- результат - урон `20`

![Рисунок 7.2. Функция получает атаку 30 и защиту 10, а возвращает урон 20](../_images/07/fig-black-box.svg)

_Рисунок 7.2. Функция как чёрный ящик_

Для использования функции достаточно знать её имя, нужные входные данные и результат. Необязательно каждый раз разбирать её внутренний код.

Основные понятия:

- **Вызов функции (function call)** - запуск функции по имени.
- **Аргумент (argument)** - значение, передаваемое при вызове, например `30`.
- **Возвращаемое значение (return value)** - результат работы функции, например `20`[^4].
- **Вызывающий код (caller)** - место программы, из которого вызывают функцию.

Как и в математике, функция может получать значения и возвращать результат. Но программная функция умеет и выполнять действия, например выводить сообщение.

### Функция в псевдокоде

Создадим функцию для расчёта урона:

```text
FUNCTION CalculateDamage(attack, defense)
    SET damage = attack - defense

    IF damage < 0
        SET damage = 0
    END IF

    RETURN damage
END FUNCTION
```

В этой записи:

- `CalculateDamage` - имя функции
- `attack` и `defense` - её параметры
- инструкции между `FUNCTION` и `END FUNCTION` - тело функции
- `RETURN damage` - возврат вычисленного результата

**Параметр (parameter)** - переменная, которая получает значение при вызове функции[^5]. _Параметр указан при создании функции, аргумент - при её вызове._

**Тело функции (function body)** - команды, выполняемые при вызове.

**Определение функции (function definition)** - полное описание функции с именем, параметрами и телом[^6]. Само определение не запускает код, функция начинает работу только при вызове.

Например:

```text
SET goblinLoss = CalculateDamage(heroAttack, goblinDefense)
```

Аргументы передаются параметрам по порядку:

| Параметр | Аргумент | Значение |
|---|---|---|
| `attack` | `heroAttack` | `30` |
| `defense` | `goblinDefense` | `10` |

> [!IMPORTANT]
>
> _Не путайте_: `attack` - параметр функции, а `heroAttack` - аргумент при вызове. Значение `heroAttack` передаётся параметру `attack`.

### Что происходит при вызове

Перепишем бой с использованием функции:

```text
SET heroHealth = 100
SET heroAttack = 30
SET heroDefense = 12

SET goblinHealth = 60
SET goblinAttack = 15
SET goblinDefense = 10

SET goblinLoss = CalculateDamage(heroAttack, goblinDefense)
SET goblinHealth = goblinHealth - goblinLoss

SET heroLoss = CalculateDamage(goblinAttack, heroDefense)
SET heroHealth = heroHealth - heroLoss

OUTPUT goblinHealth
OUTPUT heroHealth
```

Формула урона теперь записана _один раз_, а вызывается дважды. Для первого вызова `CalculateDamage(heroAttack, goblinDefense)` выполнение проходит пять шагов:

1. Программа берёт значения аргументов `30` и `10`.
2. Параметры `attack` и `defense` получают эти значения.
3. Функция вычисляет `damage = 20`.
4. `RETURN` завершает функцию и возвращает `20`.
5. Вызвавшая строка получает результат и записывает его в `goblinLoss`.

![Рисунок 7.3. Вызов CalculateDamage передаёт управление в функцию, RETURN возвращает результат 20](../_images/07/fig-call-flow.svg)

_Рисунок 7.3. Переход управления при вызове функции_

При втором вызове функция получает другие аргументы и возвращает `3`. В итоге программа выводит `40` (здоровье гоблина) и `97` (здоровье героя).

| Вызов | `attack` | `defense` | Результат |
|---|---:|---:|---:|
| Удар героя | 30 | 10 | 20 |
| Удар гоблина | 15 | 12 | 3 |

_Ключевое правило_: после возврата функции выполнение продолжается в месте её вызова, а не с начала программы.

### Изменение правила в одном месте

Если геймдизайнер решит, что урон должен быть _не меньше 1_, изменить нужно только саму функцию:

```text
FUNCTION CalculateDamage(attack, defense)
    SET damage = attack - defense

    IF damage < 1
        SET damage = 1
    END IF

    RETURN damage
END FUNCTION
```

Все её вызовы сразу будут использовать новое правило. Это практическая польза принципа DRY.

### Досрочный выход из функции

`RETURN` одновременно _отдаёт значение и завершает функцию_. Код после выполненного `RETURN` больше не запускается[^11].

Поэтому функцию можно сократить:

```text
FUNCTION CalculateDamage(attack, defense)
    IF attack - defense < 1
        RETURN 1
    END IF

    RETURN attack - defense
END FUNCTION
```

Если разница атаки и защиты меньше 1, выполняется первый `RETURN`. Иначе функция доходит до второго. Оба варианта возвращают корректный урон.

_Важно_: у функции может быть несколько `RETURN`, если они не мешают читать её логику.

### Функция без результата

Иногда функция не вычисляет результат, а выполняет действие, например сообщает о завершении волны:

```text
FUNCTION ShowWaveCleared(wave, hits)
    OUTPUT "Wave ", wave, " cleared, hits: ", hits
END FUNCTION
```

Её вызывают отдельной строкой:

```text
ShowWaveCleared(1, 4)
```

**Процедура (procedure)** - подпрограмма, которая выполняет действие и не возвращает значение. В C++ отдельного ключевого слова `procedure` нет: для такой функции используют тип `void`, который мы рассмотрим ниже.

### Копирование аргументов

Попробуем увеличить здоровье игрока через функцию:

```text
FUNCTION Heal(health)
    SET health = health + 20
END FUNCTION

SET playerHealth = 50
Heal(playerHealth)
OUTPUT playerHealth
```

Как думаете, программа выведет `50` или `70`? Правильный ответ - `50`.

При вызове `Heal(playerHealth)` функция получает отдельный параметр `health` со значением `50`. Изменение `health` не влияет на переменную `playerHealth` снаружи.

| Момент | `playerHealth` | `health` внутри функции |
|---|---:|---:|
| До вызова | 50 | - |
| В начале `Heal` | 50 | 50 |
| После увеличения | 50 | 70 |
| После завершения | 50 | - |

![Рисунок 7.4. Параметр health получает отдельную копию значения playerHealth и меняется независимо](../_images/07/fig-copy.svg)

_Рисунок 7.4. Параметр получает копию значения аргумента_

Чтобы изменить здоровье игрока, нужно вернуть новое значение и записать его в исходную переменную:

```text
FUNCTION Heal(health)
    RETURN health + 20
END FUNCTION

SET playerHealth = 50
SET playerHealth = Heal(playerHealth)
OUTPUT playerHealth
```

Теперь программа выведет `70`.

> [!IMPORTANT]
>
> _Изменение параметра `int` внутри функции не изменяет переданную переменную_. В C++ это называется передачей по значению. Другие способы передачи параметров разберём позднее.

### Какой должна быть функция

Наличие функций само по себе не делает код понятным. Следуйте простым правилам[^7]:

- _Одна функция - одна задача_. `CalculateDamage` считает урон, а не отвечает одновременно за здоровье и вывод сообщений.
- _Имя описывает действие_. Например, `CalculateDamage`, `ReadDamage`, `CountHits`.
- _Нужный программе результат возвращается_. Для расчёта урона подходит `RETURN`, а для сообщения игроку - вывод на экран.
- _Функцию легко проверить отдельно_. Чем меньше связанных обязанностей, тем проще тестирование.

Например, после изменения правила на минимальный урон `1` функция `CalculateDamage` должна пройти такие проверки:

| Случай | `attack` | `defense` | Ожидаемый урон |
|---|---:|---:|---:|
| Обычный удар | 30 | 10 | 20 |
| Ровно 1 | 11 | 10 | 1 |
| Равные значения | 10 | 10 | 1 |
| Защита выше атаки | 5 | 12 | 1 |

_Хорошая функция понятна по имени и даёт предсказуемый результат для разных входных данных_.

## Пример 1. Арена в псевдокоде

Соберём функции в программу арены из шестой главы. Условия прежние: три волны, у каждого врага 100 единиц здоровья, игрок вводит положительный урон. После каждой волны программа сообщает число ударов, а в конце выводит общий результат.

Выделим три действия:

- `ReadDamage()` - получить корректный урон
- `CountHits(health, damage)` - рассчитать число ударов по врагу
- `ShowWaveCleared(wave, hits)` - показать результат волны

Функция ввода повторяет вопрос, пока значение не станет положительным. Параметров у неё нет, поэтому скобки пустые:

```text
FUNCTION ReadDamage()
    INPUT damage

    WHILE damage <= 0
        OUTPUT "Damage must be greater than 0"
        INPUT damage
    END WHILE

    RETURN damage
END FUNCTION
```

Функция подсчёта ударов получает здоровье и урон. Она изменяет _свою копию_ `health`, поэтому здоровье из вызывающего кода не затрагивается:

```text
FUNCTION CountHits(health, damage)
    SET hits = 0

    WHILE health > 0
        SET health = health - damage
        SET hits = hits + 1
    END WHILE

    RETURN hits
END FUNCTION
```

Теперь основная программа читается как план:

```text
SET damage = ReadDamage()
SET totalHits = 0

FOR wave FROM 1 TO 3
    SET hits = CountHits(100, damage)
    SET totalHits = totalHits + hits

    ShowWaveCleared(wave, hits)
END FOR

OUTPUT "Total hits: ", totalHits
```

Здесь `FOR wave FROM 1 TO 3` повторяет тело цикла три раза. Функция `ShowWaveCleared` определена в [разделе "Функция без результата"](#функция-без-результата).

Проверим `CountHits` отдельно:

| Здоровье | Урон | Число ударов | Проверка |
|---:|---:|---:|---|
| 100 | 30 | 4 | 70, 40, 10, -20 |
| 100 | 100 | 1 | Ровно один удар |
| 100 | 150 | 1 | Урон выше здоровья |
| 100 | 1 | 100 | Долгий бой |

> [!IMPORTANT]
>
> _`hits` начинается с нуля при каждом вызове `CountHits`, а `totalHits` накапливает удары между волнами_. Эти счётчики не мешают друг другу.

Имена `damage` в `ReadDamage`, `CountHits` и основной программе обозначают разные переменные. Подробнее об области видимости поговорим в следующей главе.

## Функции в C++

В C++ не все функции нужно писать самостоятельно. Многие уже есть в **стандартной библиотеке C++ (C++ Standard Library)**. Мы пользовались `std::cout` и `std::cin`, а теперь рассмотрим ещё один пример.

Допустим, герой находится в точке `4`, а гоблин - в точке `11`. Нужно вычислить расстояние между ними, не допустить урона меньше `1` и ограничить здоровье значением `100`.

```cpp
#include <algorithm>
#include <cstdlib>
#include <iostream>

int main() {
    int heroX = 4;
    int goblinX = 11;

    std::cout << std::abs(heroX - goblinX) << '\n';
    std::cout << std::max(30 - 35, 1) << '\n';
    std::cout << std::min(90 + 20, 100) << '\n';

    return 0;
}
```

Результат:

```text
7
1
100
```

- `std::abs` возвращает модуль числа. Расстояние между точками равно `7`, а не `-7`[^8].
- `std::max` выбирает большее из двух значений. Из `-5` и `1` получаем `1`, поэтому урон не будет меньше единицы[^9].
- `std::min` выбирает меньшее из двух значений. Из `110` и `100` получаем `100`, поэтому здоровье не превысит максимум[^10].

Строки `#include` в начале программы позволяют пользоваться нужными средствами стандартной библиотеки. Для `std::abs` используется `<cstdlib>`, для `std::max` и `std::min` - `<algorithm>`, а для `std::cout` - `<iostream>`. Пока достаточно знать, что эти строки добавляют перед использованием соответствующих функций.

_Готовую функцию можно использовать, не зная, как она устроена внутри._

### Функция main

В обычной программе C++ выполнение начинается с `main`. Это тоже функция, которую вызывает среда запуска программы.

В записи `int main()`:

- `int` - тип результата
- `main` - имя функции
- `()` - отсутствие параметров в нашей программе
- `{ ... }` - тело функции
- `return 0` - успешное завершение программы

> [!NOTE]
>
> В C++ функция `main` автоматически возвращает `0`, если выполнение дошло до конца. Однако для наглядности в примерах мы пишем `return 0;` явно. У других функций, возвращающих значение, такого исключения нет.

### Определение функции

Запишем функцию урона на C++. Имена функций в нашем курсе записываем в стиле `camelCase`:

```cpp
int calculateDamage(int attack, int defense) {
    int damage = attack - defense;

    if (damage < 1) {
        damage = 1;
    }

    return damage;
}
```

![Рисунок 7.5. Части определения функции: возвращаемый тип, имя, параметры, тело и return](../_images/07/fig-function-anatomy.svg)

_Рисунок 7.5. Из чего состоит определение функции в C++_

| Часть | В псевдокоде | В C++ |
|---|---|---|
| Имя | `FUNCTION CalculateDamage` | `calculateDamage` |
| Параметры | `(attack, defense)` | `(int attack, int defense)` |
| Тело | До `END FUNCTION` | Между `{` и `}` |
| Результат | `RETURN damage` | `return damage;` |

В C++ каждому параметру указывают тип, например `int attack`.

**Тип возвращаемого значения (return type)** - тип результата функции. Его пишут перед именем, здесь это `int`, поскольку урон - целое число.

_Значение после `return` должно соответствовать объявленному типу_[^12].

### Вызов функции

В C++ функцию вызывают по имени, передавая аргументы в скобках. Вот бой героя и гоблина целиком:

```cpp
#include <iostream>

int calculateDamage(int attack, int defense) {
    int damage = attack - defense;

    if (damage < 1) {
        damage = 1;
    }

    return damage;
}

int main() {
    int heroHealth = 100;
    int heroAttack = 30;
    int heroDefense = 12;

    int goblinHealth = 60;
    int goblinAttack = 15;
    int goblinDefense = 10;

    goblinHealth = goblinHealth - calculateDamage(heroAttack, goblinDefense);
    heroHealth = heroHealth - calculateDamage(goblinAttack, heroDefense);

    std::cout << "Goblin health: " << goblinHealth << '\n';
    std::cout << "Hero health: " << heroHealth << '\n';

    return 0;
}
```

Результат программы:

```text
Goblin health: 40
Hero health: 97
```

Функция вызывается прямо внутри выражения `goblinHealth - calculateDamage(...)`. Вызов возвращает целое число `20`, поэтому выражение вычисляется как `60 - 20`.

_Возвращаемое значение можно сразу использовать в вычислении или сохранить в переменной._

### Функции типа void

Не каждая функция должна возвращать значение. Например, функция может просто вывести сообщение:

```cpp
void showWaveCleared(int wave, int hits) {
    std::cout << "Wave " << wave << " cleared, hits: " << hits << '\n';
}
```

**`void`** - тип, который в объявлении функции означает отсутствие возвращаемого значения.

Такую функцию вызывают как отдельную инструкцию:

```cpp
showWaveCleared(1, 4);
```

Она завершается после выполнения тела. При необходимости её можно завершить раньше командой `return;`, но возвращать значение нельзя.

_Разница_: `int calculateDamage(...)` отдаёт число, а `void showWaveCleared(...)` выполняет действие и результата не отдаёт. Поэтому `int x = showWaveCleared(1, 4);` не скомпилируется.

### Параметры и аргументы

При вызове C++ проверяет количество и типы аргументов. Вызов `calculateDamage(30)` с одним аргументом вместо двух приведёт к ошибке компиляции, например C2660 в Visual Studio[^13].

```text
'calculateDamage': function does not take 1 arguments
```

Но компилятор не поймёт, если вы поменяли местами два значения одного типа:

```cpp
int loss1 = calculateDamage(30, 10);
int loss2 = calculateDamage(10, 30);
```

Оба вызова допустимы. Первый вернёт `20`, а второй - `1`, потому что атака и защита поменялись местами.

> [!TIP]
>
> _Давайте аргументам понятные имена._ По `calculateDamage(heroAttack, goblinDefense)` легче проверить порядок, чем по `calculateDamage(30, 10)`.

### Передача по значению

Посмотрите, как функция пытается вылечить героя:

```cpp
#include <iostream>

void heal(int health) {
    health = health + 20;
}

int main() {
    int playerHealth = 50;

    heal(playerHealth);

    std::cout << playerHealth << '\n';

    return 0;
}
```

Программа выведет `50`, а не `70`.

**Передача по значению (pass by value)** - способ передачи аргумента, при котором функция получает отдельную копию его значения[^4]. Для обычного параметра `int health` в C++ используется именно этот способ.

Поэтому внутри `heal` меняется только копия `health`. Чтобы изменить `playerHealth`, функция должна вернуть результат, а вызывающий код - сохранить его:

```cpp
#include <iostream>

int heal(int health) {
    return health + 20;
}

int main() {
    int playerHealth = 50;

    playerHealth = heal(playerHealth);

    std::cout << playerHealth << '\n';

    return 0;
}
```

Теперь программа выведет `70`.

> [!IMPORTANT]
>
> _`heal(playerHealth)` и `playerHealth = heal(playerHealth)` - разные действия_. В первом случае возвращённое значение теряется, во втором записывается в переменную. Другие способы изменения переменной из функции рассмотрим в следующей главе.

### Объявление перед вызовом

В C++ имя функции должно быть известно в месте вызова. Если `calculateDamage` определена ниже `main`, а до `main` о ней ничего не сказано, компилятор сообщит, что имя не найдено (например, C3861 в Visual Studio)[^14][^15].

Есть два решения:

1. Поместить полное определение функции перед `main`.
2. Добавить перед `main` объявление, а определение оставить ниже.

**Объявление функции (function declaration)** - запись типа результата, имени и параметров без тела[^6]. Её завершает символ `;`.

```cpp
#include <iostream>

int calculateDamage(int attack, int defense);

int main() {
    std::cout << calculateDamage(30, 10) << '\n';

    return 0;
}

int calculateDamage(int attack, int defense) {
    int damage = attack - defense;

    if (damage < 1) {
        damage = 1;
    }

    return damage;
}
```

Здесь `int calculateDamage(int attack, int defense);` перед `main` сообщает компилятору, как вызывать функцию. Само тело функции находится после `main`.

_Не путайте_: объявление описывает интерфейс функции, а определение содержит исполняемый код.

### Функция должна вернуть значение

Если функция объявлена с результатом типа `int`, она должна вернуть значение на каждом возможном пути выполнения.

Например, этот код ошибочен:

```cpp
int calculateDamage(int attack, int defense) {
    if (attack > defense) {
        return attack - defense;
    }
}
```

Если `attack <= defense`, выполнение дойдёт до конца без `return`. Visual Studio может выдать предупреждение C4715, а использование такого результата приводит к неопределённому поведению[^18].

Исправленный вариант:

```cpp
int calculateDamage(int attack, int defense) {
    if (attack > defense) {
        return attack - defense;
    }
    return 1;
}
```

> [!IMPORTANT]
>
> _Для функции с результатом проверяйте все ветви `if` и `else`_. Исключение с автоматическим возвратом `0` относится только к `main`.

### Шаг с заходом в отладчике

В шестой главе мы познакомились с пошаговой отладкой. Теперь сравним три команды Visual Studio[^16][^17].

**Шаг с выходом (step out)** - команда отладчика, которая выполняет остаток текущей функции и возвращает управление к месту вызова.

| Команда | Клавиша | Что делает |
|---|---|---|
| _Шаг с обходом (Step Over)_ | `F10` | Выполняет вызов, не показывая шаги внутри функции |
| _Шаг с заходом (Step Into)_ | `F11` | Переходит внутрь вызываемой функции |
| _Шаг с выходом (Step Out)_ | `Shift+F11` | Выполняет остаток функции и возвращается в вызывающий код |


![Рисунок 7.6. Visual Studio после F11: отладчик остановился внутри функции SendMessage](../_images/07/vs-step-into-function.png)

_Рисунок 7.6. Переход внутрь функции в Visual Studio. Источник: Microsoft, CC BY 4.0[^16]_

На рисунке показана функция `SendMessage` из документации Microsoft. После F11 указатель выполнения перемещается внутрь функции. Точное место остановки зависит от кода и настроек отладчика.

Как выбирать команду:

- `F10` - когда внутренний код функции сейчас неинтересен
- `F11` - когда нужно искать ошибку внутри функции
- `Shift+F11` - когда нужно вернуться из функции к месту вызова

В окне _Locals_ можно увидеть параметры и локальные переменные текущей функции. Это помогает проверить, какие аргументы она получила. При стандартных настройках Visual Studio часто пропускает код сторонних библиотек.

## Пример 2. Арена на C++

Переведём арену из псевдокода на C++. Здесь три функции выполняют отдельные действия, а `main` объединяет их в программу.

```cpp
#include <iostream>

int readDamage() {
    int damage = 0;

    do {
        std::cout << "Damage (greater than 0): ";
        std::cin >> damage;

        if (damage <= 0) {
            std::cout << "Damage must be greater than 0\n";
        }
    } while (damage <= 0);

    return damage;
}

int countHits(int health, int damage) {
    int hits = 0;

    while (health > 0) {
        health = health - damage;
        hits = hits + 1;
    }

    return hits;
}

void showWaveCleared(int wave, int hits) {
    std::cout << "Wave " << wave << " cleared, hits: " << hits << '\n';
}

int main() {
    const int WAVES = 3;
    const int ENEMY_HEALTH = 100;

    int damage = readDamage();
    int totalHits = 0;

    for (int wave = 1; wave <= WAVES; wave = wave + 1) {
        int hits = countHits(ENEMY_HEALTH, damage);
        totalHits = totalHits + hits;

        showWaveCleared(wave, hits);
    }

    std::cout << "Total hits: " << totalHits << '\n';

    return 0;
}
```

Если ввести `30`, программа выведет:

```text
Damage (greater than 0): 30
Wave 1 cleared, hits: 4
Wave 2 cleared, hits: 4
Wave 3 cleared, hits: 4
Total hits: 12
```

Главное преимущество видно в `main`:

1. Прочитать положительный урон.
2. Для каждой волны подсчитать удары и сообщить результат.
3. Показать общее число ударов.

Функции остаются пригодными для других игровых задач. Например, если враги станут сильнее, достаточно передать функции `countHits` другое значение `health`.

> [!NOTE]
>
> Пример рассчитан на _числовой ввод_. Если вместо числа ввести буквы, `std::cin` перейдёт в состояние ошибки и цикл может повторяться бесконечно. Обработку некорректного ввода нужно реализовать отдельно.

### Проверка в отладчике

1. Поставьте точку останова на `int hits = countHits(ENEMY_HEALTH, damage);` и запустите программу через F5.
2. Введите урон `30`.
3. Нажмите F11. Отладчик перейдёт в `countHits`. Проверьте в _Locals_ значения `health = 100` и `damage = 30`.
4. Выполняйте F10 и наблюдайте, как `health` уменьшается, а `hits` растёт. Значение `hits` имеет смысл проверять после строки его инициализации.
5. Нажмите Shift+F11, чтобы выйти из функции, затем продолжите выполнение. Результат вызова равен `4`.

Проверка всей программы:

| Введённый урон | Ожидаемый итог | Полученный итог |
|---:|---:|---:|
| 30 | 12 | 12 |
| 100 | 3 | 3 |
| 150 | 3 | 3 |
| 1 | 300 | 300 |

### Типичные ошибки при работе с функциями

- _Не сохраняют результат_. Вызов `heal(playerHealth);` не изменит исходную переменную. Нужна запись `playerHealth = heal(playerHealth);`.
- _Ожидают изменения через обычный параметр_. Параметр `int health` получает копию значения.
- _Вызывают функцию до объявления_. Поместите определение выше вызова или добавьте предварительное объявление.
- _Передают неверное число аргументов_. Количество и типы должны соответствовать параметрам.
- _Путают порядок аргументов одного типа_. Компилятор не всегда обнаружит такую логическую ошибку.
- _Выводят результат вместо `return`_. Если результат нужен другим вычислениям, функция должна возвращать значение.
- _Не возвращают значение во всех ветвях_. Для `int`-функции это может привести к неопределённому поведению.
- _Ставят `;` перед телом функции_. Запись `int calculateDamage(int attack, int defense);` объявляет функцию, но не начинает её определение. Перед `{ ... }` точку с запятой ставить не нужно.

## Резюме

1. Повторение логики создаёт ошибки. Принцип DRY помогает хранить одно правило в одном месте.
2. Декомпозиция делит задачу на части, а функции позволяют дать этим частям имена и вызывать их.
3. _Параметры_ записывают в определении функции, _аргументы_ передают при вызове.
4. `return` завершает функцию и возвращает результат. Функция типа `void` результата не возвращает.
5. В C++ обычный параметр `int` получает копию значения. Чтобы обновить переменную, нужно сохранить возвращённый результат.
6. Функция с результатом должна возвращать значение на всех путях выполнения, кроме специальных правил для `main`.
7. Функцию нужно объявить до места её вызова. Определение дополнительно содержит тело.
8. В Visual Studio `F11` заходит в функцию, `F10` выполняет вызов целиком, а `Shift+F11` выходит из функции.
